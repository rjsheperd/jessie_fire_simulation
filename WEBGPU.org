#+AUTHOR: RJ Sheperd

* Overview

Port of the C++/CUDA fire simulation (=fire_sim_lib=) to WebGPU compute
shaders running entirely in the browser. The BD (Burn Distance) model is the
only CUDA model used in production; MT and IMT are not ported.

Status: *complete and optimized*. All four CUDA kernels ported, plus a GPU
Rothermel shader and FIM Eikonal solver that replace the original CPU
precomputation and fixed-timestep loop. See [[file:OPTIMIZE.org][OPTIMIZE.org]] for performance
history.

* Architecture

** Original (CUDA)

#+BEGIN_EXAMPLE
Browser -> Flask -> subprocess(./simulator) -> CSV -> JSON -> Canvas
                        |
                    fire_sim_lib/
                    FireSim::UpdateSpreadData()  (CPU, Rothermel)
                    BD::RunKernel()              (CUDA, 600 steps)
                        BurnDist kernel
                        CopyKernel (ping-pong)
                        TestCrownRate kernel
                        Accelerate kernel
#+END_EXAMPLE

** WebGPU (current)

#+BEGIN_EXAMPLE
Browser -> Flask /api/sim_data_manifest -> fetch data files
                                        -> pack in JavaScript
                                        -> GPU: rothermel.wgsl      (one-time)
                                        -> GPU: compact_active.wgsl  (once)
                                        -> GPU: fim_solve.wgsl       (converge)
                                        -> readback Float32Array
                                        -> Canvas animation
#+END_EXAMPLE

Falls back to the CUDA path if =navigator.gpu= is unavailable.

* Compute Shaders

** =rothermel.wgsl= — Rothermel Spread Rate Computation

Port of =FireSim::UpdateSpreadData()= (=FireSim.cpp:351-668=) and the
16-direction decomposition (=propagation.cu:73-97=). Runs once during
initialization.

One thread per cell. Reads fuel model parameters, terrain slope/aspect, and
wind field. Computes the full Rothermel surface fire model including:
- Dead/live fuel moisture weighting and extinction check
- Net fuel loading and reaction intensity
- Propagating flux ratio and heat of preignition
- Effective windspeed (wind + slope vectors, capped at 0.9 * reaction intensity)
- Elliptical spread decomposition: 8 directional max spread rates
- Burn distances to 8 neighbors: =cell_size / rate= (or =cell_size * sqrt(2) / rate=)
- Crown fire initiation parameters (I_o, RAC)
- Global maximum spread rate via atomic CAS for timestep calculation

10 bindings (9 storage + 1 uniform). Requires
=maxStorageBuffersPerShaderStage >= 10= (Apple Silicon supports this).

Inputs are packed to minimize binding count:
- =cell_ints=: =vec2<i32>= per cell — =[fuelType, fireIgnition]=
- =cell_floats=: 2 x =vec4<f32>= per cell — =[slope, aspect, windX, windY]=, =[I_o, RAC, 0, 0]=
- =fuel_models=: array of =FuelModel= structs (13 =vec4<f32>= = 208 bytes per model)

** =fim_solve.wgsl= — Fast Iterative Method (Eikonal Solver)

Replaces the fixed-timestep BurnDist loop. Solves fire arrival times via
convergent wavefront expansion. Based on Jeong & Whitaker 2008.

Each active cell propagates to 8 unignited neighbors:
#+BEGIN_EXAMPLE
T_candidate = T_cell + dist / max_spread_rate[dir * simSize + cell]
#+END_EXAMPLE

Arrival times updated via atomic compare-and-swap minimum (same IEEE 754
bitcast trick as BurnDist). Successfully updated neighbors are atomically
appended to the output active list. =dispatchWorkgroupsIndirect= uses the
output count to size the next iteration — self-terminates when the active
list empties (0 workgroups dispatched).

7 bindings: =arrival_time= (atomic u32), =max_spread_rate= (read),
=active_in= (read), =active_out= (write), =active_out_count= (atomic),
=indirect_out= (atomic), =params= (uniform).

Ping-pong: two bind groups alternate which buffer is input vs output.
Maximum iterations = =simRows + simCols= (conservative upper bound).

** =compact_active.wgsl= — Active Cell Compaction

Port of the active-cell identification logic, enhanced with atomic-append
compaction. Replaces the original bitmask approach.

One thread per cell. If the cell is ignited and has at least one unignited
neighbor, atomically appends its ID to the active index list and updates the
indirect dispatch argument via =atomicMax=.

5 bindings: =ign_time= (atomic), =active_count= (atomic), =active_indices=,
=indirect_args= (atomic), =params= (uniform).

** =burn_dist.wgsl= — Burn Distance Propagation (legacy)

Port of =kernel_BD.cu:11-85=. The original fixed-timestep fire propagation
kernel. Each active burning cell reduces burn distance to 8 neighbors by
=ROS * timestep=. When distance reaches 0, the neighbor ignites. Uses atomic
CAS min-float on =ign_time_out= — more correct than the CUDA double-atomicExch
pattern which had a race window.

Now superseded by =fim_solve.wgsl= but retained for reference and the
=run()= code path.

Reads from compacted active indices via =dispatchWorkgroupsIndirect= (only
processes cells at the fire perimeter, not the entire grid).

** =accelerate.wgsl= — Spread Rate Acceleration

Port of =kernel_common.cu:8-29=. Ramps =curSpreadRate= toward =maxSpreadRate=
over time. Dispatched every 5th timestep in the BD loop.

SoA layout: =rate[dir * sim_size + cell]= for 16 directions per cell.
Reads acceleration constant from =packed_scalars[cell].y=.

Used by the BD code path (=run()=). FIM uses =maxSpreadRate= directly
(equilibrium rates), so acceleration is implicit.

** =crown_rate.wgsl= — Crown Fire Escalation

Port of =kernel_common.cu:36-64=. Checks if surface fire intensity exceeds
the canopy initiation threshold =I_o=. If so, escalates both =curSpreadRate=
and =maxSpreadRate= to the active crown fire rate.

Reads =I_o= and =RAC= from =packed_scalars[cell]=. Dispatched every 10th
timestep. Most threads (~98.7%) exit early because =max_spread_rate <= 0=.

Used by the BD code path. FIM runs after Rothermel (which precomputes crown
parameters), so crown effects are incorporated into the initial spread rates.

** Legacy Shaders (not dispatched)

- =copy_kernel.wgsl= — Ping-pong copy between ignition time buffers. Replaced
  by dual atomic =u32= buffers with bind group swapping.
- =mark_active.wgsl= — Bitmask-based active cell marking. Replaced by
  =compact_active.wgsl= atomic-append pattern.

* Atomic Float Minimum

WebGPU only supports atomics on =u32/i32=, not =f32=. Fire arrival times need
atomic minimum updates. Solution: exploit the property that positive IEEE 754
floats have the same ordering as =u32=:

#+BEGIN_SRC wgsl
fn atomic_min_float(ptr: ptr<storage, atomic<u32>, read_write>, new_val: f32) {
    let new_bits = bitcast<u32>(new_val);
    loop {
        let old_bits = atomicLoad(ptr);
        let old_val = bitcast<f32>(old_bits);
        if (old_val <= new_val) { break; }
        let result = atomicCompareExchangeWeak(ptr, old_bits, new_bits);
        if (result.exchanged) { break; }
    }
}
#+END_SRC

This is more correct than the CUDA =atomicExch= pattern (=kernel_BD.cu:74-79=)
which has a race window between the two =atomicExch= calls where a third
thread can clobber the value.

* GPU Buffer Layout

All spread rate arrays use Structure-of-Arrays (SoA): =rate[dir * simSize + cell]=.
Per-cell scalar arrays are packed into =vec4<f32>=:
=packed_scalars[cell] = (intensity_modifier, acceleration_constant, I_o, RAC)=.
Burn distances use =f16= when the =shader-f16= extension is available (halves
bandwidth; falls back to =f32= with shader patching).

| Buffer            | Size (581K cells) | Type              | Layout           |
|-------------------+-------------------+-------------------+------------------|
| ignTimeBufA       | 2.2 MB            | =atomic<u32>=     | 1 per cell       |
| ignTimeBufB       | 2.2 MB            | =atomic<u32>=     | 1 per cell       |
| burnDistBuf       | 9.3 MB (f16)      | =f16= or =f32=   | 8 per cell       |
| maxSpreadRateBuf  | 37.3 MB           | =f32=             | 16 per cell, SoA |
| curSpreadRateBuf  | 37.3 MB           | =f32=             | 16 per cell, SoA |
| packedScalarsBuf  | 9.3 MB            | =vec4<f32>=       | 1 per cell       |
| activeIndicesBuf  | 2.2 MB            | =u32=             | 1 per cell (max) |
| fimActiveListB    | 2.2 MB            | =u32=             | 1 per cell (max) |

* JS Orchestration

=FireSimWebGPU= class (=static/js/webgpu_sim.js=):

#+BEGIN_SRC javascript
class FireSimWebGPU {
    // Two init paths:
    async init(simCols, simRows, simData)   // CPU Rothermel, pre-packed data
    async initGPU(simCols, simRows, rawData) // GPU Rothermel from raw inputs

    // Two simulation paths:
    async run(stepCount, crowningEnabled, onProgress)  // Legacy BD loop
    async runFIM(onProgress)                           // FIM Eikonal solver

    async readResults()         // Map staging buffer, return Float32Array of TOA
    getTimingReport()           // {init_ms, run_ms, readback_ms}
    getBufferMemoryUsage()      // Per-buffer byte counts
    destroy()                   // Release all GPU buffers
}
#+END_SRC

=webgpu_main.js= orchestrates the pipeline: fetches manifest, loads data
files, packs inputs, calls =initGPU()= then =runFIM()=, reads back results,
and converts to the =fire_data= format consumed by =fire_2D_map.js=.

* Correctness Verification

Validated by =test_stress.mjs= Playwright test harness:

- *V1-reference*: WebGPU output compared against C++ reference (=temp_final_tests.csv=). 95% of cells within +/-2 timesteps.
- *V2-determinism*: Two identical runs produce byte-identical output.
- *V3-symmetry*: Center ignition on flat terrain with zero wind produces approximately circular spread.
- *Numerical edge cases*: Zero wind, extreme wind (100 m/s), non-burnable fuel, zero/saturated moisture, steep slope — all pass without NaN/Inf.

* CUDA-to-WGSL Porting Notes

| CUDA                          | WGSL                               | Notes                    |
|-------------------------------+------------------------------------+--------------------------|
| =atomicExch(float*, val)=     | =atomicCompareExchangeWeak= loop   | CAS is more correct      |
| =__global__ void kernel(...)= | =@compute @workgroup_size(256) fn= |                          |
| =threadIdx.x + blockIdx.x *=  | =@builtin(global_invocation_id)=   |                          |
| =__shared__=                  | =var<workgroup>=                   | Not used in this port    |
| =atomicAdd(int*, val)=        | =atomicAdd(&var, val)=             | Direct equivalent        |
| =__syncthreads()=             | =workgroupBarrier()=               | Not needed (no shared)   |
| =tex2D()=                     | N/A                                | Not used; direct array   |
| =cudaMemcpy(H2D/D2H)=        | =writeBuffer= / =mapAsync=        |                          |
| Multiple =.cu= files          | Multiple =.wgsl= files             | =device.createShaderModule= |

Key differences:
- WGSL has no native float atomics — CAS loops required
- WGSL =array<atomic<u32>>= cannot be indexed via dynamic expressions in some contexts — use =atomicLoad/Store= at computed indices
- WebGPU limits storage buffers per shader stage (default 8, request higher via =requiredLimits=)
- =writeBuffer= is a queue operation, not an encoder operation — resolves before the next =submit=, not interleaved with command buffer operations
- =dispatchWorkgroupsIndirect= enables data-driven dispatch counts without CPU readback
